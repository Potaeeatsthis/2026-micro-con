# RoboticArmMain — Team Guide

How the firmware is split so five people can work in parallel without breaking each other.
Read this once before your first branch. Pins, clocks, timers, DMA and interrupts are in
[`core-config.md`](core-config.md). Using an AI assistant? Give it [`AGENTS.md`](../../AGENTS.md) (repo root) first.
Paths like `App/...` below are inside `RoboticArmMain/`; this guide, the tests and the CI scripts live in
`ProjectDevGuide/`, so `RoboticArmMain/` holds only the CubeIDE project.

## 2. The ten rules

1. **No pin or peripheral change on your branch.** Ask Supanut; he edits the `.ioc`, regenerates, and merges it into `master`.
2. **`main.c` gets nothing.** It only calls `app_init()` and `app_loop()`.
3. **Every `HAL_*Callback` is defined once, in `App/app_callbacks.c`.** It only routes to your module (`voice_on_sai()`, `input_on_adc()`…). CI rejects a callback anywhere else.
4. **No PWM outside `motion/`.** Modes set targets with `motion_set_target()` / `motion_jog()`; they never touch `TIM3`/`TIM4`.
5. **Interrupt code is short.** No `HAL_Delay`, no `printf`/`LOG`, no LCD, no loops over big arrays. Copy data, set a flag, return.
6. **No main-loop step may block more than a few ms** (the whole pass must stay under ~100 ms, or audio is lost). Long work is split over several passes. `app_loop()` logs any pass slower than `APP_LOOP_WARN_US`.
7. **Every DMA buffer uses `DMA_BUF`** (non-cacheable SRAM2). Add it to the table in section 6.
8. **Don't edit `app_config.h` for testing.** Use your own `App/common/app_config_local.h` (gitignored, section 4).
9. **Module state is `static`.** Other modules use your header's functions, never your variables. Anything an ISR writes and the main loop reads is `volatile`.
10. **A PR must build with 0 errors and 0 new warnings, with the default flags**, and say what you tested on the board.

## 3. How the modules talk

```text
          ISR side (fast, short)                         main loop (app_loop, in this order)
  ┌──────────────────────────────────┐        ┌──────────────────────────────────────────────┐
  │ TIM6 50 Hz: input_tick           │        │ input_step   → posts button / encoder events │
  │             safety_tick          │        │ safety_step  → posts e-stop / rail events    │
  │             motion_tick → PWM    │        │ voice_step   → CNN, posts EVT_VOICE_WORD     │
  │ SAI DMA:    voice_on_sai         │        │ pi_link_step → parses lines, posts EVT_PI_*  │
  │ ADC DMA:    input_on_adc         │        │ modes_step   → THE ONLY event consumer       │
  │ EXTI:       safety / input       │        │                active mode sets motion targets│
  │ USART6:     pi_link_on_rx_event  │        │ lcd_step     → pulls state, redraws changes  │
  └──────────────────────────────────┘        └──────────────────────────────────────────────┘
```

Three channels, each for one kind of information:

| Need | Use | Example |
|---|---|---|
| "Something happened once" | **Event** — `app_event_post(EVT_…)` from anywhere, ISR included | button press, voice word, Pi reply |
| "What is the value now?" | **Getter** in the owner's header | `input_joy_x()`, `safety_state()` |
| "Move the arm" | **Motion API** | `motion_set_target()`, `motion_jog()`, `motion_hold()` |

The LCD only reads (pull model). Other modules never draw; at most they call `lcd_show_message("OUT OF REACH", 1500)`.

## 4. Feature flags and your local config

`App/common/app_config.h` holds the defaults on `master` (everything on, except hardware that is not fitted yet).
To test only your part, create **`App/common/app_config_local.h`** (it is in `.gitignore`):

```c
/* my bench: no mics, no screen */
#define APP_USE_VOICE 0
#define APP_USE_LCD   0
```

The build then prints a warning, `app_config_local.h is active`, so you never forget it is there.
Turning a flag off means the module is not started or called; its code still compiles, so CI always checks everything.

| Flag | Default | Notes |
|---|---|---|
| `APP_USE_MOTION`, `INPUT`, `KINEMATICS`, `VOICE`, `PI`, `LCD`, `MODES` | 1 | `MODES` needs `MOTION` |
| `APP_USE_LIMIT_SWITCHES` | 0 | set to 1 only when the switches are wired (NC to GND) |
| `APP_USE_RAIL_SENSE` | 0 | set to 1 when the 10 k / 3.3 k divider is on PC3; needs `INPUT` |

## 5. Safety behaviour everyone relies on

- **No pulse at power-up** until safety allows; then the first pulse is the calibrated home pose.
- **Manual modes move only while Hold-to-Enable is held.** On release, motion freezes in the same 20 ms tick and the target is reset to the current angle, so nothing jumps later.
- **A jog that is not refreshed for 150 ms stops by itself.** Joystick modes call `manual_jog()` every pass, so a hung main loop cannot keep the arm moving.
- **After the e-stop or a servo-rail loss, motion stays blocked** until power is back **and** someone presses the touch **OK** button (`safety_confirm_restart()`).
- **A fatal fault** (`app_fault_raise(x, true)`) freezes motion until reset and lights LD3 (red).
- **LEDs:** LD1 blinking = main loop alive; LD2 = voice word detected; LD3 = fatal fault.

These are covered by host tests (49 checks). CI runs them on every PR; run them yourself with `sh ProjectDevGuide/tests/host/run.sh` (gcc on a PC; on Windows use Git Bash).

## 6. DMA buffer budget (SRAM2, 16 KB non-cacheable)

| Buffer | Module | Bytes |
|---|---|---|
| `s_audio` (640 × int32) | voice | 2560 |
| `s_rx` / `s_tx` | pi_link | 1024 + 96 |
| `s_adc_buf` (60 × uint16) | input | 120 |
| `s_probe` (boot check) | common | 32 |
| **Total** | | **≈ 3.9 KB** (≈ 12 KB free, e.g. for an LCD DMA line buffer) |

If the linker edit or the MPU region is missing, `dma_buf_check()` stops all motion at boot and prints which one.

## 7. Recipes: extending without breaking anything

**A new module (feature folder)**
1. Copy `ProjectDevGuide/docs/module_template/` to `RoboticArmMain/App/<name>/`, rename `feature` → `<name>`.
2. Add `APP_USE_<NAME>` (default 0 until it works) to `app_config.h`.
3. In `app.c`, add one line at **EXTENSION POINT 1** (init) and one at **EXTENSION POINT 3** (step), each inside `#if APP_USE_<NAME>`.
4. Put all of this in one PR.

**A new event** — append it to the right group in `app_events.h` (never renumber), write what `arg`/`v[]` mean, and handle it in the mode(s) that care.

**A new HAL callback** (a peripheral that is not routed yet) — add the function in `app_callbacks.c` under EXTENSION POINT, route by `->Instance` to one function in your module. Make it a PR to core.

**A new Pi message** — add one row to `RX_HANDLERS` in `pi_link.c` plus a handler function, and update the guide's protocol table.

**A new touch button** — add one row to `ZONES` in `lcd.c` and an `EVT_TOUCH_*` event.

**A new fault code** — append it to `app_fault.h` and say who raises it.

**A new mode** — new `mode_<x>.c` implementing `mode_ops_t`, one entry in `MODE_TABLE` in `modes.c`, one value in `arm_mode_t` (`app_types.h`). This is a core PR.

**A new pin, timer, DMA stream** — open a GitHub issue for Supanut with: signal, wanted pin, mode, why. Free EXTI lines: 1, 3, 4, 5, 6, 9. Free DMA: DMA2 Stream 4.

## 8. "Something is wrong or missing in core"

Don't patch core files on your branch to get unblocked; that is how merge conflicts and hidden bugs start.

1. Open an issue with the label `core` describing the problem (log lines help: USART3, 921600 baud).
2. Meanwhile work around it **inside your folder**, or switch the other module off in your local config.
3. Supanut fixes it on a `core/...` branch → PR → `master`. You then run `git pull origin master` on your branch.

Every placeholder that still needs real values is marked `TODO(<area>)`. Search for `TODO(` to see what is open:
`TODO(servo)` calibration, `TODO(ik)` geometry, `TODO(input)` axis directions, `TODO(lcd)` driver hookup,
`TODO(pi)` timeout, `TODO(voice)` destinations / jog vectors, `TODO(mechanical)` limit-switch map.

## 9. Before you open a PR

- [ ] `git pull origin master` into your branch, rebuild: 0 errors, no new warnings
- [ ] `app_config_local.h` is **not** in the commit (it is gitignored; double-check `git status`)
- [ ] No `.ioc`, `Core/`, `Drivers/`, `Middlewares/`, `X-CUBE-AI/` changes (unless you are Supanut)
- [ ] No `HAL_*Callback` outside `app_callbacks.c`, no `printf` in ISR code
- [ ] Tested on the board? Which flags were on? Write it in the PR description

CI (`firmware-ci`, `.github/workflows/firmware-ci.yml`) runs on every PR into `master` and must be green before merging:
**build (Debug)**, **build (Release)**, **host-tests**, **repo-rules**. If one is red, open it on the PR page, the log
says what and where. Run the same checks before pushing, from the repo root (Python 3, gcc and arm-none-eabi-gcc on PATH):

```text
python ProjectDevGuide/ci/build_firmware.py       # firmware builds with the .cproject settings, no warnings in App/
sh ProjectDevGuide/tests/host/run.sh              # host tests
python ProjectDevGuide/ci/check_rules.py          # project rules (callbacks, USER CODE, .cproject, committed files)
```
